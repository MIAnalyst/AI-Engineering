# Message Types in LangChain

> **LangChain series · Lecture 5 of 7** — Previous: [Tools In Langchain](Tools%20In%20Langchain.md) · Next: [LLM Structured Output With Langchain](LLM%20Structured%20Output%20With%20Langchain.md)

> **One-line summary:** Messages are the basic unit of context in LangChain. Every input to a model and every output from it is a message. A message carries a **role**, **content** and optional **metadata**. The four main types are **System**, **Human**, **AI** and **Tool**.

---

## 1. What Is a Message?

- Messages are the **fundamental unit of context** for models in LangChain.
- They represent the **input and output** of a model.
- They carry the **content** and **metadata** needed to represent the **state of a conversation**.

### Every message has three parts

| Part | Meaning |
|---|---|
| **Role** | Identifies the **message type** (system, user/human, assistant/AI, tool). **Super important.** |
| **Content** | The actual content. Can be **text, audio, documents**, etc. |
| **Metadata** | **Optional** extra fields (message ID, user name, token usage, ...) |

### The idea in one picture

```
 Input to the model  = message(s)   (Human, System, ...)
 Output from model   = message      (AI message)
```

- Whenever **a human gives input**, it is a **Human message**.
- Whenever **the model gives output**, it is an **AI message**.

---

## 2. The Four Message Types

| Type | Who/what it represents | Purpose |
|---|---|---|
| **System message** | The developer | **Instructions** that tell the model **how to behave**, and give context for the interaction |
| **Human message** | The user | The **user's input** and interaction with the model |
| **AI message** | The model | The **response generated by the model**, including text, tool calls and metadata |
| **Tool message** | A tool | The **output of a tool call** |

```python
from langchain.messages import SystemMessage, HumanMessage, AIMessage, ToolMessage
```

---

## 3. Two Ways to Prompt a Model

### 3.1 Text prompt (a plain string)

```python
response = model.invoke("What is LangChain?")
```

- Just a **string**. Internally LangChain treats it as a **Human message**.
- The output comes back as an **AI message**.
- You haven't told the model how to behave. You only gave a question.

**Use text prompts when:**
- you have a **single, standalone request**
- you **don't need conversation history**
- you want **minimal code complexity**

### 3.2 Message prompt (a list of messages)

```python
messages = [
    SystemMessage("You are a poetry expert"),
    HumanMessage("Write a poem on artificial intelligence"),
]
response = model.invoke(messages)
print(response.content)
```

- You pass a **list of message objects** (System, Human, AI, ...).
- Use it when you need **instructions**, **conversation history**, or more control.
- This is how **chatbot** conversations are modelled: an ordered list of messages.

| | Text prompt | Message prompt |
|---|---|---|
| Input form | A string | A list of message objects |
| System instructions | No | Yes |
| Conversation history | No | Yes |
| Best for | One-off questions | Chatbots, multi-turn, controlled behavior |

---

## 4. System Message: Controlling Behavior

A system message is an **instruction to the LLM about how to behave**. It comes first in the list.

### Example 1: simple one-liner

```python
messages = [
    SystemMessage("You are a helpful coding assistant"),
    HumanMessage("How do I create a REST API?"),
]
response = model.invoke(messages)
```

The answer is **generic**, because no language or framework was specified.

### Example 2: detailed system message

```python
messages = [
    SystemMessage(
        "You are a senior Python developer with expertise in web frameworks. "
        "Always provide code examples and explain your reasoning. "
        "Be concise but thorough in your explanations."
    ),
    HumanMessage("How do I create a REST API?"),
]
response = model.invoke(messages)
```

The answer is now **Python-specific and practical**: it picks Flask, shows install steps and code, and adds tips such as "disable debug mode in production" and "add input validation".

> **Lesson:** the **more detail** in the system message (role, expertise, style, rules), the **better and more targeted** the response.

---

## 5. Human Message with Metadata

A message can carry **metadata**. For a human message, two useful fields are `name` and `id`:

```python
human_msg = HumanMessage(
    content="Hello!",
    name="alice",       # identifies which user sent it
    id="msg_123",       # unique ID, useful for tracing
)
response = model.invoke([human_msg])
```

| Field | Use |
|---|---|
| `name` | Distinguish **different users** |
| `id` | **Uniquely identify** a message, for **tracing/debugging** |

The model replies in a friendly way, and can take the metadata into account.

---

## 6. AI Message and Conversation History

You can **create an AI message manually**, not only receive it from the model. This lets you build a fake or past conversation history.

```python
messages = [
    SystemMessage("You are a helpful assistant"),
    HumanMessage("Can you help me?"),
    AIMessage("I'd be happy to help you with that question!"),   # written by us
    HumanMessage("What's 2+2?"),
]
response = model.invoke(messages)
print(response.content)
```

- The model sees the **whole conversation**: system, human, AI, human.
- It answers the last question in context ("2 + 2 = 4").
- The demo used a **reasoning model**, so the output also includes reasoning text.

### Reading metadata from the response

```python
response.usage_metadata
```

Gives **token usage**:
- **input tokens**
- **output tokens**
- **total tokens**

This is useful for **cost tracking**.

## 7. Tool Message: Output of a Tool Call

When the LLM needs a tool, it makes a **tool call**. When the tool runs, its output comes back as a **Tool message**.

```python
ai_message = AIMessage(
    content=[],   # empty content: it is a tool call, not text
    tool_calls=[{
        "name": "get_weather",
        "args": {"location": "San Francisco"},
        "id": "call_123",
    }],
)

weather_result = "Sunny, 72°F"      # hard-coded here; normally the tool returns this

tool_message = ToolMessage(
    content=weather_result,
    tool_call_id="call_123",        # must match the tool call's id
)

messages = [
    HumanMessage("What's the weather in San Francisco?"),
    ai_message,        # model's tool call
    tool_message,      # tool's result
]
response = model.invoke(messages)   # model produces the final answer
```

### The sequence

```
Human:  "What's the weather in San Francisco?"
   ▼
AI:     tool_call → get_weather(location="San Francisco"), id="call_123"
   ▼
Tool:   "Sunny, 72°F"  (tool_call_id="call_123")
   ▼
AI:     final natural-language answer
```

| Detail | Why it matters |
|---|---|
| AI message has **empty content** | It's a request to call a tool, not text |
| `tool_calls` has `name`, `args`, `id` | Tells which tool, with what arguments |
| `tool_call_id` in the Tool message | **Links the result back** to the right tool call |
| Tool result = **context** | The model uses it to write the final answer |

## 8. Cheat Sheet

```python
from langchain.messages import SystemMessage, HumanMessage, AIMessage, ToolMessage

# Text prompt (single request, no history)
model.invoke("What is LangChain?")

# Message prompt (instructions + history)
model.invoke([
    SystemMessage("You are a senior Python developer. Be concise."),
    HumanMessage("How do I create a REST API?"),
])

# Metadata on a message
HumanMessage(content="Hello!", name="alice", id="msg_123")

# Token usage on a response
response.usage_metadata     # input / output / total tokens
```

---

## 9. Key Takeaways

1. **Messages = role + content + metadata.** The **role** identifies the type.
2. Model **input** is a Human message (and optionally System/AI/Tool). Model **output** is an **AI message**.
3. A plain **string prompt** is treated as a Human message. It is fine for single standalone requests.
4. Use a **list of messages** when you need **instructions or conversation history**.
5. **System message** sets behavior. **Detailed** system messages give **better, more specific** answers.
6. You can **hand-write AI messages** to build conversation history.
7. **Metadata** such as `name` and `id` helps with identifying users and **tracing**. `response.usage_metadata` shows **token counts**.
8. **Tool message** carries a tool's output back to the model, linked by `tool_call_id`.
